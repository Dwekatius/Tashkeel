ML_Tashkeel Work Log
====================

Created: 2026-04-24

Purpose
-------

This folder is the standalone university-project workspace for the ML
punctuation restoration stage.

The main product model, CATT v4, already preserves punctuation when punctuation
exists in the input. It does not generate missing punctuation from scratch.
Therefore the new ML task is intentionally narrow:

  input plain Arabic words
  -> predict punctuation after each word
  -> reconstruct a punctuated Arabic text
  -> pass that text into the existing v4 tashkeel model

Architecture
------------

The punctuation model is formulated as word-boundary sequence labeling.

For every Arabic word, predict exactly one label for what should appear after
that word:

  NONE
  COMMA
  PERIOD
  QUESTION
  COLON
  SEMICOLON
  EXCLAMATION

This is safer than sequence-to-sequence generation because the model is not
allowed to rewrite, delete, or invent Arabic words. It can only choose boundary
punctuation labels.

Files Created
-------------

  README.md
    Commands and workflow.

  scripts/punct_common.py
    Shared Arabic text cleanup, diacritic stripping, punctuation label logic,
    JSONL helpers, and reconstruction helpers.

  scripts/punct_modeling.py
    Shared Hugging Face token-classification dataset and inference helpers.

  scripts/build_punctuation_dataset.py
    Copies the source v4 punctuation-aware JSONL files into ML_Tashkeel/data
    and builds processed word/label JSONL files.

  scripts/train_punctuation_restorer.py
    Fine-tunes an Arabic transformer as a token classifier over word-boundary
    labels. Uses optional class-weighted loss to reduce NONE-label dominance.

  scripts/eval_punctuation_restorer.py
    Evaluates the trained punctuation model and writes detailed reports.

  scripts/punctuate_text.py
    Punctuation-only inference CLI.

  scripts/run_punctuation_tashkeel_pipeline.py
    Full pipeline CLI: punctuation model first, then existing v4 CATT tashkeel.

Data Policy
-----------

Original workspace datasets are never modified by this ML folder.

The dataset builder copies:

  datasets/arabic_tashkeel/splits/final_tashkeel_train_punct_v4.jsonl
  datasets/arabic_tashkeel/splits/final_tashkeel_eval_punct_v4.jsonl

into:

  ML_Tashkeel/data/source/

Then it creates processed ML-specific JSONL files under:

  ML_Tashkeel/data/processed/

Follow-up cleanup:

  The initial console output was noisy on Windows because Hugging Face Trainer
  progress bars, worker subprocess imports, torchao compatibility warnings, and
  torch.distributed redirect warnings interleaved with the useful metrics.

  The scripts were updated so the default training output is cleaner:

    - dataloader workers default to 0 for this ML track on Windows
    - torchao / redirect / symlink warning noise is suppressed
    - Hugging Face's built-in tqdm bars are disabled
    - a custom progress-bar callback shows finished steps / total steps,
      elapsed time, ETA, loss, learning rate, grad norm, and latest eval
      metrics in one updating bar
    - --no-progress-bar can be passed to fall back to compact line logs
