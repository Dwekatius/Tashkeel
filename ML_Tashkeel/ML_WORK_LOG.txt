ML_Tashkeel Work Log

Purpose
-------

This folder is the standalone university-project workspace for the ML
punctuation restoration stage.

The main product model, CATT v4, already preserves punctuation when punctuation
exists in the input. It does not generate missing punctuation from scratch.
Therefore the new ML task is intentionally narrow:

  input plain Arabic words
  -> predict punctuation after each word
  -> reconstruct a punctuated Arabic text
  -> pass that text into the existing v4 tashkeel model

Architecture
------------

The punctuation model is formulated as word-boundary sequence labeling.

For every Arabic word, predict exactly one label for what should appear after
that word:

  NONE
  COMMA
  PERIOD
  QUESTION
  COLON
  SEMICOLON
  EXCLAMATION

This is safer than sequence-to-sequence generation because the model is not
allowed to rewrite, delete, or invent Arabic words. It can only choose boundary
punctuation labels.

Accuracy Focus Report - 2026-04-24
----------------------------------

What we last did:

  We trained the first full supervised ML punctuation-restoration model using
  CAMeLBERT as a word-boundary token classifier. The model predicts one label
  after each Arabic word:

    NONE / COMMA / PERIOD / QUESTION / COLON / SEMICOLON / EXCLAMATION

  Baseline full model folder:

    ML_Tashkeel/models/punctuation_restorer

  Baseline training settings:

    epochs:            3
    train batch size:  32
    eval batch size:   32
    learning rate:     2e-5
    max class weight:  12.0
    precision:         bf16

Strong points:

  - The full train/eval/inference path works end to end.
  - Boundary accuracy is strong at about 91.7%.
  - Punctuation micro-F1 is solid for a first full model at about 75.6%.
  - PERIOD and QUESTION are the strongest labels:
      PERIOD   F1 about 87.9%
      QUESTION F1 about 82.8%
  - The model is recall-heavy, so it usually notices when punctuation should
    exist instead of leaving text completely flat.
  - The punctuation -> v4 tashkeel pipeline works and loads the exported v4
    CATT model on CUDA.

Weak points:

  - The model over-inserts punctuation on some live plain-text examples.
  - COMMA, COLON, and SEMICOLON have high recall but weaker precision:
      COMMA     precision about 43.2%, recall about 93.4%
      COLON     precision about 58.0%, recall about 96.2%
      SEMICOLON precision about 42.0%, recall about 71.6%
  - Exact punctuation-sequence match on the first 2,000 eval rows is about
    56.8%, so many rows are close but not perfectly punctuated.
  - EXCLAMATION has too little data to trust deeply:
      only 175 train examples and 14 eval examples.
  - A global --none-threshold up to 0.70 did not fix one observed
    over-punctuation sample, which means the model was confident in that
    wrong punctuation.

What we are going to do now:

  Run a controlled comparison experiment with weaker class weighting instead
  of replacing the current model. The baseline used max class weight 12.0,
  which likely improved recall but encouraged over-punctuation. The next run
  will use max class weight 6.0 and write to a separate output directory:

    ML_Tashkeel/models/punctuation_restorer_cw6

  Hypothesis:

    Lower class weights should reduce false-positive punctuation, improving
    precision and live readability, while keeping enough recall to restore the
    major punctuation marks.

  After that run finishes, compare:

    - punct_micro_f1
    - punct_macro_f1
    - per-label precision/recall
    - exact punctuation-sequence rate
    - live qualitative examples from test_cases.txt

  If cw6 improves precision without collapsing recall, it becomes the new
  candidate. If it loses too much recall, try an intermediate max class weight
  such as 8.0, or keep the baseline model and add per-label inference
  thresholds/post-rules.

  ML_Tashkeel/scripts/tune_punctuation_thresholds.py

It collects model probabilities on the eval set and greedily tunes per-label
confidence thresholds. This does not retrain the model; it only decides when a
predicted punctuation mark is confident enough to keep.

    set exposes real weakness on dialogue/speech punctuation.

    total predicted punctuation marks, and slightly better exact paragraph
    match.

    gold style.

    thresholding.

    rule/model.

    colon, and exclamation training examples, then retrain a comparison model.
    Threshold tuning alone cannot recover labels the model almost never emits.
