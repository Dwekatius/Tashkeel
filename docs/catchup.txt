9. Important Gotchas
--------------------
  - Unsloth cannot train CATT through its usual LLM flow.
    CATT is a custom PyTorch Lightning model, not an HF decoder LLM.

  - Windows DataLoader gets unstable above low worker counts.
    Keep num_workers low. Current working value is 2.

  - PowerShell can point at a different Python than expected.
    When in doubt, use the full Unsloth Python path explicitly.

  - Do not compare trainer val_der directly against the external eval DER.
    Use tests/eval_catt.py for real before/after comparison.

  - Some user-observed "errors" are not pure diacritization errors.
    Plain-alif vs hamza normalization and similar spelling cleanup cases are
    orthographic normalization problems, not just tashkeel.

11. Current Weaknesses
----------------------
EO is good now, but not perfect.

Main remaining weakness:
  longer formal prose

Observed pattern:
  - short and medium sentences are strong
  - long passages still show more syntax-related mistakes
  - formal prose sources like wikipedia, shamela, and quran remain the hardest

Likely reason:
  data coverage, not architecture choice

The training set is heavily skewed toward shorter rows and tashkeela-style data.
Earlier analysis found:
  - median length about 56 chars
  - p90 about 88 chars
  - only a small fraction of rows are truly long
